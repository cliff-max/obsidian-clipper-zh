# 无字幕视频 AI 转写 + 抖音支持 — 实现记录

日期：2026-10-07 ~ 2026-10-12
分支：`feat/bilibili-ai-transcribe`
状态：已实测收敛（B 站 40~110 分钟多视频全链路验证、抖音字幕轨与转写验证）

本文档记录最终落地的架构、实测中踩过的坑与既定限制，供后续维护参考。

## 1. 能力概览

| 能力 | 说明 |
|---|---|
| B 站无字幕转写 | playurl 64kbps 音轨下载 → 页面解码 → VAD 细块 → SiliconFlow ASR，无时长限制 |
| 抖音字幕轨 | `video.cla_info.caption_infos` WebVTT（兼容 `subtitle_infos`），带时间轴 |
| 抖音无字幕转写 | 原声轨（`music.play_url`）优先，回退 `play_addr`，**上限约 20 分钟 / 40MB** |
| 抖音页面范围 | `/video/{id}`、推荐/关注/精选 feed 当前视频、UP 主主页页内播放；陈列页给指引 |
| 入口 | 视频页右下角浮层；页面加载 4s 后自动探测无字幕（无需先剪藏） |

## 2. 转写管线（`background-transcribe.ts`）

两级分块：**下载/解码粗块（~5 分钟，sidx/限深扫描 + 字节网格）→ 页面端 VAD 静音切分为 ~30s 细块 → 细块并发 5 转写**。解码并发 2、ASR 并发 5 流水线并行。

关键机制（均为实测问题倒逼）：

- **时间轴**：细块起点 = 已完成块真实解码时长累计 + 块内 PCM 偏移（不用 bitrate 估算，无漂移）
- **热词**：标题+UP 主+简介（≤300 字）经 `prompt` 注入（Qwen3-ASR contextual prompting）；端点 400 拒绝时自动摘除并会话记忆
- **断点续传**：细块粒度；部分完成块重做时按时间戳回填已完成文本，不重复计费
- **签名 URL 过期**：块下载失败 → `refreshAudioUrl()` → 原地重试一次
- **CDN 轮换**：playurl 收集 `backupUrl` 候选，失败轮换并粘住可用节点；403 时经 DNR 注入 `Origin+Referer` 重试（部分受保护内容校验 Origin，页面同源请求有而 SW 没有；Origin 是 fetch 禁设头只能走 DNR）
- **429**：3s/6s/12s/24s 长退避 ×5 + 遵循 Retry-After
- **网络中断**：连续 8 次网络失败即暂停（避免烧预算），网络恢复后点击续传
- **失败三级补救**：原样重试 → 冷却 45s 换 SenseVoice（免费）→ WAV 对半拆分逐半转写（服务端对特定载荷确定性 500 与模型无关）
- **失败可见性**：占位符带时间区间与原因（`[24:38 起转写失败（HTTP 500）]`）；含失败的缓存不短路重转、提取器对半成品缓存也置需转写标记（按钮重现可补齐）
- **并发守卫**：同目标单实例（检查即登记 + finally 释放），重复触发静默拦截
- **占位 running 状态**：init 期间即对轮询可见（「转写启动中…」），init 失败落 failed 并清理心跳（防 alarm 复活循环）

## 3. 解码层（`audio-wav-encoder.ts`）

- 页面端一步完成：重对齐 → `decodeAudioData` → OfflineAudioContext 重采样 16kHz 单声道 → VAD 切分 → 逐块 WAV
- **VAD**：帧 25ms/移 10ms，短时 RMS，阈值 = `min + 0.1×(max−min)`（动态范围法；能量近均匀时判无可切点交硬切），静音 ≥300ms 为切点，目标 30s（10~45s），尾块不足 10s 并入前块
- **重对齐 `realignFragmentedAudio`**：box 链完整头部（init）+ 从链断点后首个完整 moof 续接——字节网格硬拆的块起点落在 fragment 中间时由此可解码（实测某流 box 链早断，整计划落在网格上）
- **计划构建限深 ≤8MB**：其余交网格（历史 bug：全文件扫描把 74MB 预下载一遍，init 分钟级且网络抖动即整体失败）
- Range 响应 200 全量时按请求区间截取（防 init+整文件拼坏块）

## 4. 抖音数据链路

- **桥**（`douyin-bridge.ts`）：manifest `document_start + world:MAIN` 注册（Safari 回退标签注入），拦截页面自身已签名的 `/aweme/v1/web/`、`/aweme/v2/web/` 响应按形状吸收（`aweme_detail`/`aweme_list`）——**扩展永不算 a_bogus**。实测 PC 推荐流走 `/aweme/v2/web/module/feed/`（v2！），详情走 `/aweme/v1/web/aweme/detail/`
- **SSR 兜底**：`__UNIVERSAL_DATA_FOR_REHYDRATION__`（现行页面已不存在）+ `RENDER_DATA`（URL 编码，仅壳配置）仅作历史形态探测，数据实际全靠桥
- **feed 当前视频**：视口内 `a[href]` 的 `aweme_id`/`gid`/`/video/{id}` 候选取视口中心最近者；UP 主主页需检测到播放中的大 video（模态）才提取，`modal_id` 优先
- **图集判定**：仅 `images` 数组（`media_type:4` 在普通长视频上也会出现，勿用）
- **音频 CDN 白名单**：douyin.com / douyinvod.com / **douyinstatic.com**（原声轨实际域名）/ amemv.com / bytecdn.cn 等；下载经 DNR 注入 Referer
- **消息上限**：扩展消息 64MiB，音频 base64 膨胀 4/3——抖音整段下载上限 40MB；块响应按 ≤10min 块预算控制

## 5. 提取器行为（两平台共性）

- 站内 URL 命中即**永不回退 defuddle 整页解析**（推荐流/消息面板混入主体的历史问题）；接口失败给 meta 兜底 + 可读原因
- B 站字幕轨三级回退（匿名 wbi → DNR cookie → 页面上下文）+ 双重采样防钓鱼假轨 + 时长校验
- 「需转写」标记：确认无字幕（或缓存为半成品）时写入，浮层据此显隐；剪藏与自动探测都会维护

## 6. 已知限制（用户文档同步）

1. 抖音转写上限约 20 分钟 / 40MB（消息通道与解码内存约束；更长需流式解码改造）
2. 充电专属等权益内容的音频被 CDN 全节点拒绝（已轮换 + Origin 注入后仍 403）——平台权限边界
3. ASR 无句级时间戳（SiliconFlow 端点仅返回纯文本）——30s 块锚 + 块内插值；`transcribe-client` 预留 verbose_json/segments 解析，换端点可自动升级
4. 抖音 feed/主页的「当前视频」靠视口启发式，选错可从标题识别（待反馈收紧）
5. 纯 BGM 无语音视频转写为空 →「无可转写语音」提示
